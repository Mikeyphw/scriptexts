# Repository layout

`userscripts/standalone/` contains direct single-file userscripts. These files are both editable source and install artifacts.

`userscripts/builders/content-site-modernizer/` is a shared builder for modern dark mobile-first content-site interfaces. MenOfPorn Modern UI, Putinho Modern UI, Gayteam Modern UI, JustTheGays Modern UI, STR8UPGAYPORN Modern UI, Bleeding Cool Modern Reader, and AIPT Comics Modern Reader are all generated from shared runtime/profile pairs. The shared runtime is kept as editable JavaScript in `src/core/runtime.template.js`; the builder loads it through `src/core/runtime.mjs`. Profile-driven sites share live PageTual/feed-state reconciliation, accessible drawers, focus-visible UI, visible filter reset status, summary/excerpt card rendering, and load-more behavior.

`userscripts/builders/manga-reader-modernizer/` and `userscripts/builders/sims-cc-download-basket/` are independent builders. Their `dist/*.user.js` files are install artifacts, while `src/` and the builder files are the source of truth.


`tools/smoke/` contains optional repo-wide Playwright Python smoke runners. Builders register smoke targets in builder-local config files, such as `userscripts/builders/content-site-modernizer/smoke.config.json`, but the Python virtual environment, browser cache, PageTual injection, screenshots, and JSON result output are owned by the repo-level runner. Normal validation compiles and checks the smoke config only; browser execution is opt-in through `PLAYWRIGHT_SMOKE=1` or manual `npm run smoke:*` commands.

`extensions/*/src/` contains editable browser-extension source. `extensions/*/dist/` contains rebuilt unsigned packages and checksums. Uploaded upstream ZIP/XPI snapshots are not retained as source.

Every installable userscript must include:

- `@namespace https://github.com/Mikeyphw/scriptexts/userscripts/<script-slug>`
- `@updateURL https://raw.githubusercontent.com/Mikeyphw/scriptexts/main/<path>.meta.js`
- `@downloadURL https://raw.githubusercontent.com/Mikeyphw/scriptexts/main/<path>.user.js`

## Smoke evidence

Repo-wide browser smoke utilities live under `tools/smoke/`. Builder-specific smoke targets are registered by config files such as `userscripts/builders/content-site-modernizer/smoke.config.json`. Runtime output is intentionally ignored under `smoke-results/`, including JSON summaries, Markdown reports, screenshots, post-injection HTML snapshots, console logs, and Playwright traces.

### Repo-wide smoke live baselines

Accepted live baseline snapshots live under `tools/smoke/live-baselines/`. The content-site modernizer baseline starts empty and is populated only by explicit live smoke capture/update commands, keeping normal validation browser-free and deterministic.

### PageTual compatibility contract v2

The content-site smoke runner includes an opt-in PageTual contract that simulates the difficult next-page cases: multiple appends, duplicate page payloads, appends while a no-match search filter is active, and restoring visible cards after that filter is cleared. Normal validation stays browser-free; run it manually with:

```bash
npm run smoke:content-sites:pagetual:focused -- --trace retain-on-failure --snapshot retain-on-failure
```

Use `npm run smoke:content-sites:pagetual` to run the same contract across every configured content-site fixture.

## Content-site onboarding tools

`tools/content-sites/new-site.mjs` is the shared-runtime site onboarding generator. It creates the profile, placeholder or copied fixtures, contract test, smoke config entry, and repo-manifest registration for a new `content-site-modernizer` target.

`tools/content-sites/fixture-refresh.mjs` reads smoke evidence and produces a fixture refresh plan. Its apply mode backs up the current fixture before replacing it, and it refuses retained smoke snapshots unless `--allow-smoke-snapshot` is explicitly passed.

### Accessibility smoke contract

`tools/smoke/run-content-site-smoke.py` exposes `--a11y-contract` for shared content-site runtime accessibility checks. Root package scripts `smoke:content-sites:a11y` and `smoke:content-sites:a11y:focused` run the contract through the existing optional Playwright environment; normal validation remains browser-free.

## Content-site visual regression lane

Visual regression thumbnails are repo-wide smoke tooling, not a builder-local virtualenv. The runner is `tools/smoke/run-content-site-visual.py`; accepted baselines live under `tools/smoke/visual-baselines/content-site-modernizer/`; evidence is emitted to `smoke-results/content-site-modernizer-visual/`.

Commands:

```bash
npm run smoke:content-sites:visual:capture
npm run smoke:content-sites:visual:compare
npm run smoke:content-sites:visual:focused
```

The lane is opt-in, Playwright-backed, and excluded from normal Devtool validation unless explicitly invoked.

## Content-site profile schema

`userscripts/builders/content-site-modernizer/src/core/profile-schema.mjs` defines schema v1 for shared-runtime profiles. The build step validates unique profile IDs, install outputs, semver-ish versions, HTTPS match rules, allowed userscript grants, navigation actions, selector shape, and capability prerequisites before writing `dist/*.user.js` files.

Use `npm run content-sites:profiles:check` from the repo root to run the browser-free profile contract. The site onboarding generator imports the same defaults, so newly scaffolded profiles start with the same normalized layout, performance, selector, and capability shape as the existing sites.

## Content-site final seal

`tools/content-sites/final-seal.mjs` is the browser-free release-readiness gate for `userscripts/builders/content-site-modernizer`. It verifies profile schema health, generated output freshness, smoke config coverage, manifest coverage, and docs markers without launching Playwright.

Commands:

```bash
npm run content-sites:seal
npm run content-sites:seal:json
```

The builder-local alias is `npm run seal` from `userscripts/builders/content-site-modernizer/`. Use this before optional browser lanes such as PageTual, a11y, live drift, and visual regression checks.

## Content-site release packs

Content-site release bundles are generated by `tools/content-sites/release-pack.mjs` through `npm run content-sites:release-pack`. The default ZIP path is `release/content-site-modernizer/content-site-modernizer-userscripts.zip` and the generated archive contains:

- `scripts/*.user.js`
- `meta/*.meta.js`
- `manifest.json`
- `checksums.sha256`
- `RELEASE_INDEX.md`

The `release/` directory is ignored because release packs are derived artifacts. Commit the generated `dist/*.user.js` and `dist/*.meta.js` files, not the ZIP.

### Managed smoke Python environment

Repo-wide Playwright smoke tests are run through `tools/smoke/with-smoke-env.sh`.
The helper prefers uv, creates `.venv-smoke`, installs `requirements-smoke.txt`,
sets `PLAYWRIGHT_BROWSERS_PATH`, and runs the requested command with the venv
activated only for that subprocess. `tools/smoke/activate-smoke-env.sh` provides
an interactive source/deactivate path for manual debugging.

### PageTual ingest final seal

The content-site final seal includes browser-free source checks for the repaired PageTual ingest path: marker compatibility, hidden-root inclusion, skipping already-enhanced cards, direct `pagetual:insert` ingest, `PAGETUAL_SCRIPT` fallback, and the managed `PLAYWRIGHT_SMOKE=1` validator gate.

The browser lane is still explicit. With `PLAYWRIGHT_SMOKE=1`, Devtool validation runs `npm run smoke:content-sites:interactions:managed -- --pagetual "$PAGETUAL_SCRIPT" --trace retain-on-failure --snapshot retain-on-failure`; without it, validation stays offline-friendly.
